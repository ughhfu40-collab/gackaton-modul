# Модус Пульс

Внутренняя система обратной связи для ГК «Модус Трейд». Сотрудник видит, кто отвечает за его обращение, когда ждать ответа и чем закончилось рассмотрение. Координатор связывает повторяющиеся обращения из разных отделов, ведёт пилот улучшения и сообщает результат авторам.

[Онлайн-демо](https://modus-pulse-022823.tantetra8.chatgpt.site) доступно владельцу. Для независимой проверки жюри используйте серверную версию из этого репозитория.

## Быстрый запуск

Понадобится **Node.js 22.13 или новее**. Внешние ключи, файл `.env`, Docker и установка npm-зависимостей для демо не требуются.

```sh
git clone https://github.com/ughhfu40-collab/gackaton-modul.git
cd gackaton-modul
npm start
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). При первом запуске создаётся SQLite-база `data/pulse.db` с 20 синтетическими обращениями из задания и двумя дополнительными случаями. Демо открывается под координатором. Роль меняется в верхней панели. Если после выхода понадобится снова войти в демо, используйте логин `lead` и тестовый пароль `pulse-demo`.

Команда проверки — `npm test`. Для нового прогона на чистых демоданных задайте новый путь к базе, например `PULSE_DB_PATH=data/defense.db npm start` в Bash или Zsh.

## Роли и личный кабинет

| Роль | Что можно сделать |
|---|---|
| Сотрудник | Подать проблему, предложение или благодарность. Видеть свои обращения, срок ответа, переписку, запросы на уточнение и решение. |
| Руководитель | Обрабатывать обращения своего подразделения и назначенные ему. Запрашивать уточнения, менять ответственного и статус. При отказе указывать отдельную причину. |
| Координатор | Обрабатывать очередь всех отделов, связывать похожие обращения и публиковать результаты пилота. |
| Администратор | Настраивать категории, сроки и ответственных, создавать приглашения по отделам. |

В личном кабинете отображаются роль, отдел и личные обновления. Сотрудник видит последние обращения и счётчики, включая заявки, которые ждут его уточнения. Отображаемое имя можно изменить отдельно для каждого аккаунта.

### Регистрация по приглашению

1. В серверном демо выберите администратора и откройте **Маршрутизация → Создать приглашение**.
2. Выберите отдел и скопируйте код. Приглашение действует 24 часа и используется один раз.
3. Выйдите через личный кабинет. Нажмите **Регистрация сотрудника** и введите имя, рабочую почту, код и пароль от 12 символов.
4. После регистрации откроется личный кабинет. Для повторного входа используйте почту и пароль. Отдел берётся из приглашения, роль всегда **Сотрудник**.

## Что показать жюри

1. **Подача.** Создайте обращение с категорией, приоритетом и при необходимости одним вложением до 2 МиБ. Система присваивает номер, выбирает ответственного по правилу категории и рассчитывает срок первого ответа. Заявки без владельца попадают в ручную очередь.
2. **Уточнение.** Откройте `A-011` в очереди координатора, запросите детали. Переключитесь на сотрудника отдела продаж и ответьте. В карточке видна история обеих сторон.
3. **Повторяющаяся проблема.** Под координатором привяжите `A-011` к `P-001`. Там уже находятся два тестовых обращения из других отделов. Заполните план, срок проверки, показатель, исходное и целевое значения.
4. **Результат.** Опубликуйте промежуточное обновление. Оно появится в истории. Для публикации итога укажите фактическое значение и вывод, сохраните этап **Результат проверен** и сообщите итог авторам.
5. **Аналитика.** В обзоре видны открытые и просроченные обращения, доля завершённых, среднее время первого ответа и доля ответов в срок. Сводку можно сверить с очередью и её фильтрами.

Сценарий на три минуты и демонстрационные показатели есть в [DEMO.md](DEMO.md).

## Что учтено при работе

- **Одновременное редактирование.** Обращения и карточки общих проблем имеют версии. При конфликте интерфейс открывает актуальную запись, подставляет изменённые поля из старой формы и просит их сверить перед повторным сохранением.
- **Уведомления.** Промежуточное сообщение появляется в истории и обновлениях, сохраняя текущее решение и время первого ответа.
- **Истечение сессии.** При отправке формы с истёкшей сессией приложение предложит снова войти. Черновик остаётся в памяти открытой вкладки и восстанавливается только для того же аккаунта. После перезагрузки вкладки черновик пропадает.
- **Языки.** Интерфейс доступен на русском, казахском и английском. Тексты обращений и комментариев остаются на языке автора.

## Устройство и границы MVP

| Режим | Хранение и доступ |
|---|---|
| Серверный через `npm start` | Node.js и SQLite. Серверные сессии, регистрация, проверки доступа к заявкам и вложениям. |
| Статическое браузерное демо | Синтетические данные и изменения в хранилище браузера. Доступны тестовые роли, кабинет и рабочий сценарий. |

Статическую версию можно запустить локально командой `python3 -m http.server 8080 --directory dist` и открыть [http://127.0.0.1:8080](http://127.0.0.1:8080). Для проверки регистрации и прав доступа используйте сервер.

В MVP сроки считаются в календарных часах, похожие обращения связывает координатор, а значения эффекта пилота в сценарии тестовые. Подтверждение почты, самостоятельное восстановление пароля, корпоративный вход и интеграции с облачным Битрикс24 и 1С относятся к следующему этапу. Для сетевого запуска используйте HTTPS-прокси и параметры из [.env.example](.env.example). Настройки можно загрузить командой `node --env-file=.env server.mjs`.
